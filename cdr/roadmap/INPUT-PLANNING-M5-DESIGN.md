# Input Phase Planning (M5)

## Overview
Design of the cross-platform input/event system, focus management, and application loop. Implementation will follow this specification in subsequent milestones without blocking existing rendering code.

## Goals
- Unified event abstraction (keyboard, mouse, resize, focus) decoupled from backend specifics.
- Focus traversal model compatible with nested widget hierarchies (composition API).
- Blocking event loop (phase 1) with future extensibility for async streaming.
- Non-invasive integration with existing widget rendering (widgets opt-in to focus & input handling).

## Event Model
Primary event categories:
1. Keyboard: KeyEvent (KeyCode + char? + modifiers)
2. Mouse: MouseEvent (coordinates, button, kind, modifiers)
3. Resize: ResizeEvent (new width/height)
4. Focus: FocusEvent (gained/lost notifications) — internally generated.

Unified interface:
- IInputEvent with Type discriminator (enum InputEventType) and strongly typed record structs accessed via pattern matching.

### Key Codes & Modifiers
- KeyCode enumeration includes navigation, function keys (F1–F12), common control keys (Enter, Escape, Tab, Backspace, Delete, Home, End, PageUp, PageDown), arrow keys, Character (for printable graphemes), plus potential extended codes.
- KeyModifiers: Flags (Ctrl, Alt, Shift, Meta).

### Mouse Model
MouseEventKind enumeration: Move, ButtonDown, ButtonUp, ScrollUp, ScrollDown, Drag.
MouseButton enumeration: Left, Middle, Right, X1, X2.
Coordinate origin: Same as buffer (0-based top-left). Future: capture relative container offsets through composition mapping service.

### Resize Events
Generated by backend capability (terminal size polling or direct notification). Debounced (optional) to avoid thrash on rapid resizes.

## Focus Management
Introduce IFocusableWidget interface (optional for any widget needing focus).

FocusManager responsibilities:
- Maintain ordered list of focus entries (reference + optional priority/z-order).
- Provide Next(), Previous(), Set(index), and Set(widget) operations.
- Emit FocusEvents when focus changes (old loses, new gains).
- Optional FocusTraversalPolicy to customize ordering (default: linear registration order).

Widgets integrating focus:
- Implement IFocusableWidget { bool CanFocus { get; } void OnFocusGained(); void OnFocusLost(); }
- Registration occurs during composition (WidgetComposer could accept focusable widgets).

## Application Loop
Initial synchronous loop outline:
```
while (!cancellationRequested)
{
    var evt = backend.ReadEvent(); // blocking / poll
    dispatcher.Dispatch(evt);
    if (evt is ResizeEvent) layoutService.Invalidate();
    if (evt requires redraw) terminal.Draw(renderRoot);
}
```

Phase 1: Implement InputLoop with Run(CancellationToken, Action<IInputEvent>) and ability to inject a poll provider.
Phase 2: Upgrade to async streaming (IAsyncEnumerable<IInputEvent>) and merge with rendering scheduler.

## Backend Integration Strategy
- Add ITerminalInputBackend (optional extension) with TryReadEvent(out InputBackendRawEvent rawEvent).
- Adapter layer converts raw events to IInputEvent (maps escape sequences for keyboard, mouse tracking sequences, SIGWINCH / size queries).
- Fallback: If backend does not implement input interface, provide polling stub generating Resize events only.

## Initial Data Structures
- InputEventType (enum): Key, Mouse, Resize, Focus
- Records: KeyEvent, MouseEvent, ResizeEvent, FocusEvent
- Wrapper: InputEvent (readonly struct with union-like fields) OR pattern use (e.g. interface + specific records).

## Threading & Concurrency
Phase 1: Single-threaded loop (input then render). Ensure thread-safe modifications for FocusManager if accessed inside event handlers.
Phase 2: Move to dedicated input thread or rely on async enumerable with cancellation.

## Error Handling & Logging
- InputLoop logs unknown escape sequences at Debug level.
- Repeated unknown sequences aggregated (optional) to avoid log spam.

## Extensibility Hooks
- PreDispatch filter: Func<IInputEvent, IInputEvent?> (drop/transform events).
- Key binding service (later) maps KeyEvent -> Command objects.
- Accessibility: Focus events can later emit ARIA-like metadata (planned future extension).

## Open Questions / TODO
- Mouse drag semantics (threshold vs immediate).
- Multi-modifier chord timing (e.g., distinguishing Ctrl+Alt combinations consistently across OS).
- Grapheme-aware Character KeyEvent (currently char only; future: full grapheme codepoint aggregation).
- Scroll wheel granularity normalization.

## Implementation Sequence (Incremental)
1. Define core types (records, enums, interfaces).
2. Implement FocusManager and IFocusableWidget.
3. Stub InputLoop with a dependency on IInputSource (interface for backends).
4. Provide TestInputSource for unit tests (scripted events).
5. Integrate loop into sample composition test (simulate key navigation among focusable widgets).
6. Add basic key navigation (Tab/Shift+Tab) inside FocusManager.
7. Add resize simulation test.

## Out-of-Scope For M5 (Later Milestones)
- Async pipeline (M5+1).
- Key binding / command mapping service.
- Advanced mouse drag tracking & gesture recognition.
- Accessibility metadata broadcast.
